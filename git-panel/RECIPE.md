# git-panel

A repository overlay for the Herdr desktop app: a colored commit graph with everyday git buttons, a view of branches, tags, stashes and the reflog (with the local writes ADR-007 allows: branch and tag creation, detached checkout, cherry-pick and revert at a commit, branch rename and merged-branch delete, stash push, apply, pop and drop, and abort of an operation in progress), a GitHub pull-request browser (with the two-click merge, close, ready-for-review and delete-branch actions of ADR-009) and a read-only view of the git configuration. `ctrl-shift-g` opens it on the repo of the focused terminal; click a commit to read its message and diff, click a pull request to see its checks, reviews and files.

![git-panel](preview.png)

## What you see

An overlay, 1200 × 900 (`mod.json`: `{ "place": "none", "overlay": { "width": 1200, "height": 900 } }`), with a 10 px rounded frame, a 1 px border and the theme background. Every color is a theme token (`accent`, `ansi1`–`ansi6`, `ansi10`, `muted`, `dim`, `border`, `hover`, `selected`, `raised`, `popover`); nothing is hard-coded. Monospace text uses the theme's mono font.

Top to bottom:

1. **Tabs row**, 46 px: `Graph`, `Refs`, `Pull requests` and `Config`, 14 px text, each with a 15 px icon (`graph.svg`, `branch.svg`, `pr.svg`, `settings.svg`; accent on the active tab, `dim` on the others), a 2 px accent underline under the active one. No title.
2. **Controls row**, 46 px, per tab.
   - Graph: a branch chip (accent border, branch icon, name truncated at 220 px, a 12 px `chevron-down.svg`), then `↓n` (ansi3) and `↑n` (ansi2) behind/ahead as 20 px tinted pills, an `N changed` pill (ansi3, the entries `git status` lists: tracked changes plus untracked files, a new untracked folder counting once, and nothing untracked when `status.showUntrackedFiles=no`) and an `N conflicts` pill (ansi1), when the branch has a pull request (wide layout) a 24 px rounded chip `PR #n <Draft|Open|Merged|Closed>[ · review decision]` with an 8 px CI dot, in ansi2 (open), `muted` (draft), ansi5 (merged) or ansi1 (closed), a 200 px bordered `Search commits` input (only when the overlay is wider than 820 px) with the match position (`3/12`, muted; `12 matches` before the list has moved to one; `No match` in ansi1, `No match in loaded commits` when more can be loaded) and `↑` `↓` buttons when there are several matches, and on the right the buttons `Fetch`, `Pull`, `Push`. Buttons are 28 px high, 12 px side padding, 6 px radius, 1 px border, 13 px text, each with a 14 px tinted icon (`fetch.svg`, `pull.svg`, `push.svg`, `branch.svg`; see Icons below). Pull and Push turn ansi3 / ansi2 while the branch is behind / ahead.
   - Refs: four list buttons `Branches`, `Tags`, `Stashes`, `Reflog` with the item count after the name (each with its own icon; the active one is tinted accent) and a `Reload` button with the reload icon. Under `Stashes` a 220 px `Stash message (optional)` input and a `Stash changes` button come before `Reload` (the button is disabled while an operation runs or the working tree is clean).
   - Pull requests: three filter buttons `Open`, `Merged`, `Closed` (icons `pr`, `merge`, `pr-closed`; the active one is tinted accent) and a `Reload` button with the reload icon.
   - Config: scope buttons `All`, `Local`, `Global` (the active one has an accent border), a 260 px bordered filter input and a `Reload` button.
3. **Note bar**, only while an operation runs or has a result: at least 30 px high, plain text. Running is muted on a `raised` background with an accent bar on its left edge, success is ansi2 (`Fetch: done`, cleared after 5 s, except the notes that carry a recovery command, which stay until clicked away or replaced by the next action's note) and failure is ansi1, each on a 14-alpha tint of its color with a 3 px bar of that color on the left; a failure holds the last four lines of git's or gh's message. No spinner and no check icon.
4. **Body.** When a list has nothing to show, its message (`Loading history…`, `No commits`, `No open pull requests`, `Not a git repository`, an error in ansi1) is centered over the list area, in `dim`.
   - Graph: a list of 28 px rows. Left, a lane column 16 px per lane (at most 10 lanes) wide: 2 px vertical lane lines in a palette cycling `accent, ansi2, ansi3, ansi5, ansi6, ansi1, ansi4, ansi10`, rounded bends where a lane joins or branches off, and an 8 px node (filled; a merge commit's node is hollow with the lane color as border; the checked-out commit gets a 14 px accent ring around a filled core). Then ref chips (20 px high, 12 px text, tinted fill plus border in the chip color: current branch accent, filled stronger and semibold; tag ansi3, remote branch ansi4, local branch ansi2; at most three, a `+n` in `dim` counts the rest), the commit subject (muted for merge commits), the short hash (60 px, mono, dim), the author (130 px, muted) and the relative time (105 px, dim). The selected row has a 2 px accent bar on its left edge. Under 560 px width the hash and author columns are dropped and the time becomes the 7-character hash.
   - Refs: 28 px rows in mono for names. Branches: a `●` (accent) and a tinted row for the current one, the name (semibold when current), the upstream (`no upstream` in `dim` when none) with `↑n` ansi2, `↓n` ansi3 or `gone` ansi1 pills, the last subject, a `merged` pill (ansi5, not on the current branch), and in the wide layout the short hash and relative time. Tags: the name in ansi3, an `annotated` pill (ansi5), the subject, and in the wide layout hash and time. Stashes: `stash@{n}` in accent, the message, the short hash (wide) and the time; the open one has the accent bar and `selected` background. Reflog: `HEAD@{n}`, short hash, message and time, all `dim` except the message. A 34 px footer counts the items.
   - Pull requests: a list of 32 px rows: an 8 px CI dot (ansi1 fail, ansi3 pending, ansi2 pass, border color when there are no checks), `#number` (52 px, dim), the title, a branch chip (ansi4, up to 260 px), the author (120 px, wide layout only) and the age (90 px, dim).
   - Config: 28 px rows grouped by section. A heading row (12 px, uppercase, `dim`) starts each section; a setting row shows the scope (62 px, colored: local ansi2, global ansi4, system ansi5, worktree ansi6, command ansi3), the key (mono, accent, 280 px; 180 px in the narrow layout), the value (mono, flexible, `(no value)` when empty) and, in the wide layout, the file it came from (240 px, dim). A 34 px footer reads `N settings · read-only; later scopes override earlier ones`.
5. **Detail panel** below the list, only after a selection.
   - Commit: 340 px high, a 40 px header (accent short hash, `N files changed`, total `+n` ansi2 and `−n` ansi1), the message (first 60 lines: the subject at 15 px semibold, a `dim` 12 px `author <email> · date` line, a `Committed by …` line only when the committer differs, a 30 px row with the full hash in mono and a `Copy` button (`cx.write_to_clipboard`), a `Parent`/`Parents` row of accent short hashes that select the parent and scroll its row to the middle of the list, or show a note when it is not in the loaded graph, then the body in muted text) and a list of changed files (28 px mono rows: a tinted 18 px status badge A ansi2 / D ansi1 / other ansi3, the path with its directory in `dim` and the file name in the text color, `+n` ansi2, `−n` ansi1).
   - Pull request: 440 px high, a 40 px header with `#number`, the title and the buttons `Checkout`, `Open in browser`, `Hide`. Under the header, when an action applies, a 44 px action row (the body is 44 px shorter, so the panel stays 440 px): open non-draft PR: `Method` and the toggle `merge` / `squash` / `rebase` (the chosen one in accent; default `merge`), `Merge` (dimmed, with the reason in `dim` beside it, while `mergeBlock()` says no: draft, conflicts, behind, blocked, checks failing or still being worked out); open draft: `Ready for review`; open: `Close PR`; merged PR from this repository: `Delete branch`. An armed button turns ansi1 (`Click again to merge #n (squash)` / `close #n` / `mark #n ready` / `delete <branch>`). Wide layout: two columns, the left (info) flexible and the right (`FILES (n)`) 440 px with a left border. Narrow layout: the same two blocks stacked, each half of the height. The info column has the title (15 px semibold), the state chip (`Draft` muted, `Merged` ansi5, `Closed` ansi1, `Open` ansi2), `head → base`, `+additions −deletions N files`, a row of merge-state and label chips (open PRs: `Ready to merge` ansi2, `Blocked: checks or reviews required` / `Behind its base branch` / `Merge allowed, checks failing` ansi3, `Has conflicts` ansi1; up to 8 labels in `muted`, `+n` for the rest), `Review requested: <logins>` in `muted`, a CHECKS list (8 px state dot, name, state; `fail` in ansi1 and `pending` in ansi3, the rest `dim`), a REVIEWS list (author, state in ansi2 for approved and ansi1 for changes requested) and the description rendered as markdown.
   - A clicked file replaces the panel body with its diff: 22 px rows, two 44 px line-number gutters, an 18 px `+`/`−` column, added lines on an ansi2 tint and removed lines on an ansi1 tint (the color at alpha `30`), hunk headers on a `raised` row with the range in accent, and the changed words inside a changed line highlighted. A `‹ Files` button (commit) or `‹ Details` button (PR) in the header returns to the list. On the Graph tab a commit's file diff also has a `History` button in the header (`Diff` while the history shows): the body becomes a 30 px note row (`N commits touched it up to this commit (renames followed). Click one to jump to it.`) over a list of 28 px rows, each with the short hash (accent, mono), the subject, the author (wide layout) and the relative time; the row of the open commit has the `selected` background.
6. **Footer**, Graph only, 44 px, when more history exists: `Showing N commits` and a `Load more` button (adds 400).
7. **Branch menu**: a 380 px popover at (14, 50) with a filter input and 28 px rows, up to 380 px high. Rows show `●` and a faint accent background for the current branch (semibold), a small `remote` pill in ansi4 for remote-only branches, and a first row `Create branch "<typed>"` in accent when the typed name is valid and does not exist.

## How it behaves

- **Which repo.** `props.folder` pins it to one folder. Otherwise it follows the focused pane (its cwd, or the space folder; on a remote machine it runs there). It shows `Not a git repository` when there is none, `No commits yet` for an empty repo and `Loading history…` while reading.
- **Opening.** `mod.open:git-panel` toggles the overlay (pressing the key again closes it). A tab or pane works too: `herdr-app do tab.new --mod git-panel --props '{"folder":"/repo","tab":"prs","state":"merged","pr":8}'`. Props: `folder` (path), `tab` (`graph` | `prs` | `config`; default is the tab last used), `state` (`open` | `merged` | `closed`), `pr` (a positive integer, preselects that PR), `scope` (`all` | `local` | `global`; the Config tab's scope filter, default `all`), `prChip` (`false` never shows the current-branch PR chip; otherwise it is shown once the Pull requests tab has been opened in that view). The `ctrl-shift-g` overlay is opened by `mod.open`, which takes no props, so there the only control is not opening the Pull requests tab. The last graph read for each folder is kept at module scope, so reopening paints at once and refreshes in the background.
- **Refresh.** Every 5 s, and when a watched folder changes (local repos). The graph is re-read only when the refs, HEAD, branch, ahead/behind or limit changed. The PR list is re-read at most once a minute unless a filter changes.
- **Graph reads** use `git log --branches --remotes --tags HEAD --date-order -n 400` plus `for-each-ref`, `rev-parse`, `symbolic-ref`, `rev-list --left-right --count @{upstream}...HEAD`, `status --porcelain=v2 -z --no-renames` (the pills), `rev-parse --git-path` for the markers `MERGE_HEAD`, `rebase-merge/head-name`, `rebase-apply/rebasing`, `rebase-apply/applying`, `CHERRY_PICK_HEAD` and `REVERT_HEAD` (in this order, first match wins, as in git: a rebase can leave `CHERRY_PICK_HEAD` behind while it picks a commit), which `readTextFile` probes (the banner; a failure only hides it), and `config --get branch.<name>.merge`, all read-only (`--no-optional-locks`, `core.fsmonitor=false`). The status and banner state do not enter the graph signature; a change in them only repaints.
- **Guarded writes** (ADR-007, `docs/decisions/ADR-007-allow-guarded-local-writes.md`): every one goes through `op()`.
  - On a selected graph commit (not a stash, not a file diff) a 44 px row sits under the panel header: a 170 px `Branch or tag name` input, a flexible `Tag message (optional)` input and the buttons `Branch here` (`git branch <name> <hash>`), `Tag here` (`git tag <name> <hash>`, or `git tag -a <name> -m <msg> <hash>` when a message is typed) and `Check out (detached)` (`git switch --detach <hash>`). The inputs are created in `init()` and cleared after a success. The name must pass `validRefName()` (no leading `-` or `.`, no `..`, no trailing `/`, `.` or `.lock`) and then `git check-ref-format refs/heads/<name>` or `refs/tags/<name>`, run by `op()` as `extra.check` before anything is written; a refusal shows as a note and nothing runs.
  - Under `Refs > Stashes`, `Stash changes` runs `git stash push --include-untracked [-m <msg>]`. With a stash open, a 44 px bar between the list and the diff shows `stash@{n}` with `Apply` (`git stash apply <hash>`, by hash, so a shifted list cannot apply another stash) and `Pop` (`git stash pop stash@{n}`; the first click turns it into `Click again to pop` on an ansi1 border for 5 s via `confirm("pop:<stash@{n}>:<hash>")`, the second runs it, after `rev-parse --verify stash@{n}` still equals the clicked hash). Two entries can hold the same commit, so the open entry is `v.refsStash` (`stash@{n}`), only that row is highlighted, and clicking the other entry of the same commit moves the bar to it; a push or drop that shifts the index keeps the entry open under its new `stash@{n}` (when two entries hold the same commit it follows the first of them, and the bar always names the entry that Pop or Drop will act on). A bar with a `Drop` button (`git stash drop stash@{n}`, the same two clicks and `rev-parse` check) sits beside `Pop`. The success notes of Pop and Drop stay up until clicked away (`extra.keep`) and carry the hash and `git stash store <hash>` to bring the entry back. If git reports `No local changes to save` (exit 0), the note says nothing was stashed instead of "done".
  - Under `Refs > Branches` a row is clickable (the list's `on_item_click`, keyed by branch name; the open row has the accent bar and `selected` background) and a 44 px bar appears under the list: the name, a 200 px `New branch name` input, `Rename` (`git branch -m -- <old> <new>`; the new name is checked like any other; one click) and, only for a branch that is `merged` and not the current one, `Delete (merged)` (`git branch -d -- <name>`, never `-D`; `Click again to delete` on an ansi1 border for 5 s via `confirm("del:<hash>:<name>")`, so arming one branch never arms another that points at the same commit, then `rev-parse --verify refs/heads/<name>` must still equal the clicked hash). Its success note stays up and carries the hash and `git branch <name> <hash>`. Git applies its own merged check too.
  - In the commit detail header, `Cherry-pick` (`git cherry-pick <hash>`) and `Revert` (`git revert --no-edit <hash>`) sit before `Close` (graph commits only). Each needs two clicks on the same commit and the same branch (`Click again to cherry-pick`/`revert`, ansi1; the key is `<kind>:<hash>:<branch>`, so it does not fire after HEAD moved to another branch). A merge commit is refused with a note (git needs `-m`), so is a detached HEAD, and right before running `op()` checks that `status --porcelain --untracked-files=no` is empty and that `merge-base --is-ancestor <hash> HEAD` agrees: a revert needs the commit in HEAD's history, a cherry-pick needs it outside it (otherwise a note says there is nothing to revert, or that the commit is already there). On a conflict or an empty result git leaves the operation in progress and the banner takes over.
  - The in-progress banner has an `Abort <merge|rebase|cherry-pick|revert>` button (none for `APPLYING PATCH`): `Click again to abort` on an ansi1 border for 5 s via `confirm("abort:<operation>:<id>")` (the label names the operation; `<id>` is the text of the marker file that names it, such as the commit being merged; a refresh that sees the operation end or change, even to another of the same kind, drops the arm; for a rebase through the apply backend the marker is empty, so its id is empty and only its kind identifies it), then `op()` re-reads which operation is in progress (`inProgress()`) and refuses when it is no longer that very one (same kind and id) before running `<op> --abort`. This is the only write allowed while `inprog` is set, and it discards the work done on that operation so far, which the banner text says; git may not be able to rebuild uncommitted changes that existed before the operation began. Continuing or finishing is left to a terminal.
  - Nothing runs while `inprog` is set (merge, rebase, cherry-pick, revert, patch): `writeBlock()` shows `MERGING: finish it in a terminal, or use Abort in the banner, first` (for a patch, which has no Abort button: `finish or abort it in a terminal first`) and stops. Every button of these writes ignores a click that only dismissed the branch menu (`blocked()`).
  - A conflict from `apply` or `pop` (git keeps the stash; only the conflicts pill shows it, because a stash conflict leaves no `MERGE_HEAD` for the banner to find, and git's own refusals then stop further stash or switch writes), a hook, or a signing setup that prompts (`tag.gpgSign` for a tag, `commit.gpgSign` or a commit hook for a cherry-pick or revert) is not handled by the mod: git's text shows in the note bar, `op()` ends the command at its 120 s timeout, and the user finishes it in a terminal.
- **Search** looks only at the loaded rows: a case-insensitive substring of the subject, author or a ref name, or the start of the hash. Rows that do not match are dimmed (subject and author in `dim`), never removed, so the lanes stay intact; the match the list last moved to has an accent tint at alpha `26` (not drawn on the selected row, whose own background wins). While the box is hidden (overlay not wider than 820 px) the search counts as empty, so nothing stays dimmed with no way to clear it; the text comes back when the overlay is widened, but the current match is forgotten, so the next `Enter` starts again from the first match. The arrow buttons ignore a click that only dismissed the branch menu (`blocked()`). Typing jumps to the first match, `Enter` and `Shift+Enter` (the input's `submit` event) or the arrow buttons step through them, wrapping around. `hits()` memoizes on the rows array and the text, so it costs nothing while neither changes; it runs from `renderPanel()`, never from the row renderer. The list scrolls with a `VirtualListScrollHandle` made in `init()`. No git command runs for a search.
- **Clicking a commit** loads its message and changed files; clicking the same commit again closes the panel. Clicking a file shows that commit's diff for the file; a merge commit shows the diff against its first parent.
- **Fetch** runs `git fetch --all --prune`. **Pull** runs `git pull --ff-only` and is disabled on a detached HEAD. The label becomes `Pull ↓n` when behind.
- **Push** needs two clicks: the first turns the button into `Click again to push ↑n` with an ansi1 border for 5 s, the second runs it. It never forces. A branch that never had an upstream runs `git push -u origin HEAD`; a branch whose upstream was set but no longer exists on the remote is refused with a note instead of being re-published. A detached HEAD shows `Detached HEAD: switch to a branch to push`.
- **Branch menu.** Click the chip, type to filter. A local branch runs `git switch <name>`, a remote-only one `git switch --track <remote/name>`, the create row `git switch -c <name>`. New names must match `^[A-Za-z0-9_][A-Za-z0-9._/-]*$`, contain no `..`, and not end in `/` or `.lock`. Branch names that start with `-` are never listed.
- **One operation at a time.** While one runs the others are ignored. When it ends the graph is re-read.
- **Menu click-through.** There is no occlusion in gpui-kit, so clicks that dismiss or pick from the menu would also hit what is under it; the view ignores clicks while the menu is open and for 400 ms after it closes.
- **Pull requests** (needs `gh`): `gh pr list --state <open|merged|closed> --limit 50 --json …` in gh's default order (the age column shows the last update); an empty list reads `No <state> pull requests`. `Reload` re-reads it. Clicking a row loads `gh pr view <n> --json …` and `gh pr diff <n>`; clicking the row again closes the panel. `Checkout` runs `gh pr checkout <n>` (one click, a local branch switch). `Open in browser` runs `gh pr view <n> --web` and is hidden for a repo on a remote machine. `Hide` only closes the panel. The four GitHub writes (`prwrites.js`, ADR-009) take two clicks each on the same target: `gh pr merge <n> --repo <host>/<owner>/<repo> --merge|--squash|--rebase --match-head-commit <oid>`, `gh pr close <n> --repo …`, `gh pr ready <n> --repo …` (the repository always comes from the PR's URL, so a changed `gh` default or remote cannot aim a write at another repository), and for a merged same-repository PR `gh api --hostname <host> -X DELETE repos/<owner>/<repo>/git/refs/heads/<branch>` (the remote branch only; owner, repo and host come from the PR's URL). Right before a write `gh pr view <n> --repo … --json state,isDraft,mergeable,mergeStateStatus,headRefOid,baseRefName` is read again and the write is refused if the head commit changed (for a merge: or the base branch) or the state no longer fits; Delete branch also refuses the default branch, a branch that is the base of an open PR, a branch that is gone or moved. The mod never creates or reviews a PR, never uses the admin, auto-merge or branch-delete flags of `gh pr merge`, and never touches a local branch. Close, Ready and Delete leave their note up until clicked away; it names how to undo. After a success the list, the Graph chip and the open detail are read again.
- **Refs** (`refs.js`): five read-only git calls, run when the tab opens and on every refresh while it shows (the view repaints only when the output changed): `for-each-ref --sort=-committerdate` on `refs/heads` with `%(upstream:track)`, `for-each-ref --merged HEAD` (the `merged` pill), `for-each-ref --sort=-creatordate` on `refs/tags`, `stash list -n 100` and `reflog -n 100`. In `for-each-ref` formats a unit separator is `%1f`; in `log`-style formats it is `%x1f`. Without a commit `--merged` and `reflog` fail, which counts as an empty list, not an error. Clicking a stash runs the same `select()` as a commit (`git show` of the stash hash, `-m --first-parent`, so the tracked changes against HEAD; untracked files stashed with `-u` are not listed) and shows the shared commit detail panel (`detailPanel(t, mono, commit)`), so a file click opens its diff. Moving into or out of the Refs tab closes the open commit or stash, because that panel is shared; the graph's "close if it is not in the log" check is skipped on this tab. Stash rows are keyed by their entry (`stash@{n}`), not the hash, because two entries can hold one commit and the list throws on a duplicate key; the click maps the entry back to the hash. The tag hash is the commit an annotated tag points at (`%(*objectname)`). Tag and reflog rows are not clickable; branch and stash rows open their action bar.
- **Config** (`config.js`): `git config --list --show-origin --show-scope -z`, read on opening the tab and on every refresh while it shows; the view repaints only when the output changed. Entries are sorted by section and keep git's order inside one, so a key set in several scopes appears once per scope and the later one wins. The filter matches key, value and file. Masking is best effort and applies to keys and values: a setting is shown as `••••••` when its name (the part after the last dot) contains `pass`, `token`, `secret` or `extraheader`; a URL's `user:password@` or long token before `@` becomes `••••••@` (a plain `git@` stays), including inside keys such as `url.<base>.insteadOf`; a `proxy` value's `user:password@` is masked even without a scheme; an assignment whose name contains `pass`, `token` or `secret` (`password=…`, `GH_TOKEN=…`, `client_secret='…'`, as in an inline credential helper) keeps its name and quote and has its value replaced by `••••••`. The filter runs on the masked text. The tab never writes configuration. It shows `Not a git repository` outside a repo.
- **Errors** from git or gh show as text in the note bar, or in the list area when the list itself fails.

## Built from

- `main.js`, default-exporting a class that extends `View` (`init(props, cx)`, `render`), from `gpui-kit` (`View`, `div`, `svg`) and `gpui-base` (`v_flex`, `h_flex`, `InputState`, `Input`, `Scrollbar`, `v_virtual_list`, `VirtualListScrollHandle`, `TextView` in `prs.js`). It holds the state and refresh logic; everything else is a module of plain functions that take the view as `v` (the class forwards `button`, `small`, `field`, `pill`, `emptyState`, `op`, `confirm`, `writeBlock`, `refuse`, `clearSel`, `select`, `jumpTo`, `setDiff`, `diffView` and `detailPanel` to them, which is what the tab modules call).
- `render.js` (`renderPanel`), `ops.js` (`op`, `confirmAction`, `writeBlock`, `refuse`, `fetchAll`, `pull`, `push`), `writes.js` (`createRef`, `pickCommit`, `abortOp`, `detachHead`), `detail.js` (`selectCommit`, `clearSel`, `jumpTo`, `copyHash`, `detailPanel`), `diff.js` (`pickFile`, `setDiff`, `diffView`), `graph.js` (`commitRow`, `drawLanes`, `refChip`), `log.js` (`parseLog`, `matches`, `layout`), `menu.js` (the branch menu), `search.js` (`hits`, `goHit`, `nextHit`, `searchBox`), `ui.js` (widgets), `shared.js` (`READ`, `ROW`, `LANE`, `MAX_LANES`, `PAGE`, `ABORT`, `alpha`). Behavior is the same as when they were one file; the element ids keep their `gg-` prefix.
- `status.js`: `parseStatus()` counts `git status --porcelain=v2 -z` entries and `inProgress()` names the operation in progress (`MERGING`, `CHERRY-PICKING`, `REVERTING`, `REBASING`, `APPLYING PATCH`). Read-only; `main.js` calls both from `refresh()`.
- `refs.js`, the Refs tab: parsers (`parseBranches`, `parseTags`, `parseStashes`, `parseReflog`), the toolbar and the virtual lists `gg-refs-list-<section>` (28 px). It takes the view as `v` and keeps its state under `refs*` names.
- `config.js`, the Config tab: parsing and masking (`parseConfig`, `maskKey`, `maskValue`), the toolbar, the virtual list `gg-cfg` (28 px). It takes the view as `v` and keeps its state under `cfg*` names.
- `prs.js`, the Pull requests tab and the Graph tab's PR chip: list rows, detail panel, `gh` calls, `loadCurrentPr()` and `prChip()`. It takes the view as `v` and keeps its state on it under `pr*` names (`prHead*` for the chip).
- `prwrites.js`: `mergePr`, `closePr`, `readyPr`, `deleteHeadBranch` (each: `confirmAction`, then `op()` with a `check(run, gh)` that re-reads the PR), `mergeBlock()`, the arm keys (`pr-merge:<host>/<owner>/<repo>#<n>:<base>:<oid>:<method>`, `pr-close:…#<n>:<oid>`, `pr-ready:…#<n>:<oid>`, `pr-delbranch:…#<n>:<branch>:<oid>`) and `prActionBar()`. `clearPr()` drops an armed `pr-*` key; the merge method is `v.prMethod`.
- `history.js`: `toggleHistory()` reads `git --literal-pathspecs log --follow -n 100 --format=%H%x1f%an%x1f%ar%x1f%s <open commit> -- <path>` for the open file (READ flags; the history starts at the open commit, and a file name is never read as a pathspec pattern), `fileHistoryView()` shows it in the detail body and `parseHistory()` parses it. State is `v.fileHist` (`{ path, rows, loading, error }`); the object's identity guards a late read. Read-only.
- `herdr` functions: `spaces`, `panes`, `focused` (where the focused terminal is), `exec` (every git and gh call, argv array, no shell, `cwd` set to the repo root), `readTextFile` (the in-progress probe), `watchFolder`, `theme`, `settings`, `props`.
- Virtual lists with `on_item_click` on the list: `gg-list` (commits, 28 px), `gg-prs` (PRs, 32 px), `gg-branches` (menu, 28 px), `gg-refs-list-branches` and `gg-refs-list-stashes` (28 px), `gg-fhist` (file history, 28 px), `gg-diff` (22 px).
- Icons: 24 px stroke SVGs (`currentColor`, stroke 2, Lucide style) in the mod folder, drawn through `svg("mods/git-panel/<name>.svg").text_color(...)`. Every button (`button()` 28 px, `small()` 26 px in `ui.js`, both built by `chip()`) takes an `icon`. Without a `tone` the label is `foreground` on a `border` outline and the icon takes its tint from the `TINT` table in `ui.js` (fetch ansi4, reload ansi6, pull ansi3, push ansi2, merged and history ansi5, destructive ansi1, ...). A `tone` (the armed second click ansi1, the chosen filter accent, a suggested Pull ansi3 / Push ansi2 when behind / ahead) tints the fill (alpha `18`), border (`66`), label and icon; hover darkens it (`30`), pressed uses `selected`. Disabled is `dim`, inert. An icon-only button (the search `↑`/`↓`) is square and carries a `tooltip`. Files: `branch branch-plus fetch reload pull push more chevron-down copy back history diff tag checkout external hide merge close ready trash rename undo cherry archive restore check ban up down pr pr-closed graph settings`.
- Programs run: `git` and, for the Pull requests tab, `gh`.
- Key binding, in `keys.json`: `{ "global": { "ctrl-shift-g": "mod.open:git-panel" } }`.

## Watch out

- No handlers inside a `v_virtual_list` renderer: put them on the list (`on_item_click`).
- No `occlude`: see the menu click-through rule above.
- Children of a scrolling column need `flex_none`, or wrapped lines overlap. Give every panel a fixed pixel height or the scroll columns spill out.
- Never reuse a `cx` after an `await`; use the one the async callback receives. `cx.timer` exists on async contexts.
- `mod.open` is a toggle: it closes an already open overlay.
- `herdr-app check <mod folder>` only renders the initial state, so handlers and later states are never exercised by it. Take a picture with `herdr-app shot file.png` after opening a temporary tab with `tab.new --mod git-panel --props …`, then close it with `tab.close --id <tab> --confirmed true`.
- A throwaway demo repo is best for screenshots (the preview was taken on one with fake authors); the Herdr sidebar shows workspace names, so crop to the overlay.
- Do not add a spinner or check-mark state to the note bar; status is plain text on purpose.
- Never add a write outside the set of ADR-007 (no `reset`, `clean`, `restore`, starting a `rebase` or `merge`, `--continue` or `--skip`, `branch -D`, `stash clear`, force push, `--no-verify`, GitHub writes) without a new decision; keep the README Security section in step with every subcommand.
- The Pull requests tab writes to GitHub only through `prwrites.js` (ADR-009): no create or review, no admin or auto-merge, no local branch deletion through `gh`. `gh pr merge`/`close` with their branch-delete flag also delete the local branch, which is why Delete branch is a separate `gh api` call. `gh api` needs `--hostname` taken from the PR's URL, or a GitHub Enterprise repository would be sent to github.com. A base branch with a merge queue may queue a merge instead of performing it. GitHub's ref delete takes no expected commit, so a push between the last check and the DELETE of Delete branch cannot be detected (ADR-009 known gap; the commits stay in the repository).
- The Config tab is read-only by design and masks credentials; do not add editing or show raw URL credentials without the user asking.
- Push never uses force and never re-publishes a branch whose remote was deleted; keep both.

## Done when

- `herdr-app check git-panel/mods/git-panel` prints `check passed` and `node --check` passes for every `*.js` in the mod folder.
- Opening the overlay on a repo with branches and merges shows the graph with colored lanes, ref chips, authors and relative times, and the branch chip shows the current branch.
- At a selected commit, `Branch here` and `Tag here` create the ref at that exact commit and leave HEAD where it was (an existing name, `-x`, `a..b`, `x.lock`, `a//b` and an empty name are refused with a note), `Tag here` with a message makes an annotated tag, and `Check out (detached)` moves HEAD to it. None of the three runs during a merge or rebase.
- Under `Refs > Stashes`, `Stash changes` stashes tracked and untracked changes (the button is disabled on a clean tree); `Apply` on an open stash applies it and keeps it; `Pop` needs a second click within 5 s and removes the entry; after another stash was pushed, applying, popping or dropping the stash you clicked still acts on that stash, not on whichever now sits at its old index (a pop or drop is refused with a note when `stash@{n}` no longer is it). `Drop` also needs a second click, and its note shows `git stash store <hash>`.
- Under `Refs > Branches`, clicking a branch opens its bar: `Rename` renames it (an existing name, an invalid name or the same name is refused with a note); `Delete (merged)` only shows for a merged branch that is not the current one, needs a second click, and refuses when the branch has moved since the list was read; the note after a delete stays up with the command that recreates it.
- At a commit, `Cherry-pick` and `Revert` need a second click within 5 s, refuse a merge commit, a detached HEAD and a tree with uncommitted tracked changes, and on a conflict leave the operation in progress; the banner then shows `Abort cherry-pick` (or `revert`), which needs a second click, discards the operation's work and clears the banner. `Abort` is offered for a merge, rebase, cherry-pick or revert, not for `APPLYING PATCH`.
- `Fetch`, `Pull` and `Push` show `↓n` and `↑n` when the branch is behind or ahead, and `Push` needs a second click within 5 s.
- In a repo whose branch had its upstream deleted on the remote, `Push` shows the refusal note and runs nothing.
- Typing in `Search commits` dims the non-matching rows without moving the lanes, shows the match count and scrolls to the first match; `Enter` goes to the next one and `Shift+Enter` to the previous one; clearing the text restores every row.
- On the Graph tab, a file's diff has a `History` button: it lists up to 100 commits that touched the file (renames followed), and clicking one selects it in the graph and scrolls to it (a commit outside the loaded graph shows the usual note); `Diff` goes back; the button is absent on the Refs tab.
- On a branch with a pull request, a chip `PR #n Open · approved` with a CI dot sits after the pills; clicking it opens that PR in the Pull requests tab; on a branch without a PR, with `gh` missing or signed out, or with `{"prChip":false}`, no chip shows and nothing else changes. Until the Pull requests tab has been opened in that view (`v.prUsed`, set by `setTab("prs")` or by opening on that tab) the Graph tab never runs `gh`; afterwards `loadCurrentPr()` runs from `refresh()` and when the Graph tab is selected, only while the layout is wide (the chip needs the room), at most once a minute per repo and branch.
- A PR's detail shows `Ready to merge`, `Blocked: checks or reviews required`, `Behind its base branch`, `Merge allowed, checks failing` or `Has conflicts` (open PRs only, from `mergeable` and `mergeStateStatus`), label chips and `Review requested: <logins>`.
- Clicking a commit shows its message and files; clicking a file shows a diff with two gutters and highlighted changed words.
- On the Pull requests tab, `Open`, `Merged` and `Closed` list up to 50 PRs, a row opens the detail panel with checks, reviews, the markdown description and files, and a file opens its diff.
- `Checkout` switches to the PR's branch, `Open in browser` opens the PR page, and `Hide` only closes the panel.
- On an open, clean, non-draft PR the action row shows the method toggle and `Merge`; one click only arms it (`Click again to merge #n (method)`, ansi1, back to normal after 5 s, on another PR, on `Hide` or when the method changes), a second click merges. A draft shows `Ready for review` instead of `Merge`; `Close PR` shows on every open PR; `Delete branch` shows on a merged PR from this repository, and a fork's PR, an unmerged one, the default branch, a base of an open PR, or a branch that moved is refused with a note (use a throwaway repository to try it).
- On the Refs tab, `Branches` lists the local branches with upstream, `↑`/`↓`, `gone` and `merged`, `Tags` marks annotated tags, `Stashes` lists stashes and a click shows their files and diff, `Reflog` lists the last 100 entries; the counts on the buttons match `git branch`, `git tag`, `git stash list` and `git reflog` (the last two up to 100).
- On the Config tab, settings are grouped by section with their scope and file, `Local` and `Global` narrow the list, the filter matches key, value and file, and a remote URL with `user:token@` and a `url.<base>.insteadOf` key with a token show `••••••@`, and `sendemail.smtppass` and `http.extraHeader` show `••••••`.
- With `{"pr":8}` and `{"tab":"prs"}` in the props the PR tab opens with PR 8 selected; `{"pr":-5}` or `{"pr":"8a"}` select nothing.
