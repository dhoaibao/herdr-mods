# git-panel architecture

## Scope

How the `git-panel` mod (`git-panel/mods/git-panel/`) is built today: a Herdr desktop-app overlay with a commit graph tab, a Refs tab (branches, tags, stashes, reflog), a GitHub pull-request tab and a read-only git config tab. What it shows and how it behaves is in [`git-panel/RECIPE.md`](../../git-panel/RECIPE.md); this page covers structure and data flow.

## Components

| Part | Where | Role |
| --- | --- | --- |
| `GitPanel` view | `main.js` | The one `View` subclass Herdr instantiates. Holds all state (`init()`), the folder and refresh logic (`where()`, `ctx()`, `watch()`, `refresh()`), `setTab()` and `blocked()`. Its other methods only forward to the feature modules below (`button`, `small`, `op`, `select`, `detailPanel`, ...): they are the small interface the tab modules call on `v`. `location()` finds the focused terminal's folder; `CACHE` and `LAST_TAB` outlive the overlay. |
| Shared constants | `shared.js` | `READ` (read-only git flags), `ROW`/`LANE`/`MAX_LANES`/`PAGE`, `ABORT` (the abortable operations), `alpha()`, `guarded()` (ignore a click that only dismissed the branch menu) and `clipDiff()`/`DIFF_LINES` (the 2000-line diff cut). |
| Commit list parsing | `log.js` | Pure: `parseLog()` splits `git log` output into commits, `matches()` is the search test, `layout()` assigns each commit a lane and the joins/branches per row. |
| Widgets | `ui.js` | `button`, `small`, `field`, `pill`, `emptyState`, `tabButton`: element builders that take the view as `v`. |
| Write path | `ops.js` | `op()` (the one place a git write runs), `confirmAction()` (the two-click guard), `writeBlock()`, `refuse()`, `switchBranch()` and the toolbar's `fetchAll`, `pull`, `push`. |
| Guarded writes | `writes.js` | `createRef`, `pickCommit` (cherry-pick, revert), `abortOp`, `detachHead` and `writeTarget`; each goes through `op()` and `confirmAction()` ([ADR-007](../decisions/ADR-007-allow-guarded-local-writes.md)). |
| Search | `search.js` | `hits()` (memoized matches among the loaded rows), `goHit`, `nextHit`, `searchBox`. |
| Branch menu | `menu.js` | Open and close, `loadBranches`, `menuItems`, `checkout`, and the menu panel. |
| Graph rows | `graph.js` | `commitRow()` (one list row), `drawLanes()` (the lane art) and `refChip()`. |
| Commit detail | `detail.js` | `selectCommit`, `clearSel`, `jumpTo`, `copyHash` and `detailPanel()` (header, message, file list, branch/tag actions). |
| File diff | `diff.js` | `pickFile` (reads one file's diff, notes when it was cut at 2000 lines), `stepFile` (previous/next file), `setDiff`, `markWords`, `diffRow`, `diffView`. |
| Render | `render.js` | `renderPanel()`: tab strip, toolbar of the shown tab, note bar (kept notes show `Click to dismiss`), in-progress banner (every tab), commit list, load-more bar and the tab panels. |
| PR tab and chip | `prs.js` | Functions that take the view as `v` and keep their state on it under `pr*` names (loading, selection, checkout, the toolbar and the panel); see its exports. `loadCurrentPr()` also runs `gh pr view` for the checked-out branch, but only after the Pull requests tab was opened in this view (`v.prUsed`) and while the layout is wide (at most once a minute per repo and branch; any failure means no chip), and `prChip()` draws the Graph tab's chip; the `prChip: false` prop turns it off for good. `readPr()` loads the detail and `reloadPr()` re-reads the list, chip and open detail after a GitHub write. |
| PR writes | `prwrites.js` | The guarded GitHub writes of [ADR-009](../decisions/ADR-009-allow-guarded-pull-request-writes.md): `mergePr`, `closePr`, `readyPr`, `deleteHeadBranch`, `mergeBlock()`, the arm keys and `prActionBar()`. Each takes two clicks and runs through `op()` with a `gh` pre-read (`extra.check(run, gh)`) that must still match what was clicked. Imports `ops.js` and `refs.js`; `prs.js` imports it and passes a reload callback, so there is no cycle. |
| File history | `history.js` | `toggleHistory()` reads `git log --follow` for the file open in the commit detail panel, `fileHistoryView()` lists the commits and a click jumps to one through `jumpTo()`. State is `v.fileHist`. Read-only. |
| Working-tree state | `status.js` | `parseStatus()` counts the entries and conflicts that `git status --porcelain=v2 -z` lists (an untracked folder is one entry); `inProgress()` names a merge, cherry-pick, revert, rebase or `git am` in progress by probing marker files under the git dir (`rev-parse --git-path` plus `readTextFile`). Pure reads; `refresh()` stores the result in `work` and `inprog`. |
| Refs tab | `refs.js` | Same pattern as `prs.js` with `refs*` state: five read-only reads (`for-each-ref` for branches, merged branches and tags, `stash list`, `reflog`), pure parsers (`parseBranches`, `parseTags`, `parseStashes`, `parseReflog`), the toolbar and the virtual lists. The lists are read-only; the only writes in this file are the branch and stash actions of ADR-007 (`renameBranch`, `deleteBranch`, `stashChanges`, `applyStash`, `removeStash` for pop and drop) and the branch Switch (`switchBranch()` from `ops.js`, shared with the branch menu), all run through the view's `op()`. Branch, tag and reflog entries can be shown in the Graph tab (`showInGraph`: `setTab` then `jumpTo`, read-only). It also owns `validRefName()`, shared with `menu.js` and `writes.js`. A stash opens in the commit detail panel (`detail.js`) through the view's `select()` and `detailPanel(t, mono, commit)`. |
| Config tab | `config.js` | Same pattern as `prs.js` with `cfg*` state: runs `git config --list --show-origin --show-scope -z`, `parseConfig()` splits it into settings, `maskKey()` and `maskValue()` hide credentials in keys and values, then the toolbar and panel render them. Read-only. |
| Icons | `*.svg` | `branch`, `fetch`, `pull`, `push`, `more`; drawn in the button text color. |
| Placement | `mod.json` | Overlay, 1200 x 900. |
| Key | `git-panel/keys.json` | `ctrl-shift-g` -> `mod.open:git-panel`. |

External surface (all from Herdr's built-in modules, typed by the generated `gpui-kit.d.ts`): `gpui-kit` (`View`, `div`, `svg`), `gpui-base` (layout helpers, `Input`, `v_virtual_list`, `VirtualListScrollHandle`, `TextView`), `herdr` (`spaces`, `panes`, `focused`, `exec`, `readTextFile`, `watchFolder`, `theme`, `settings`, `props`).

## Flow

1. **Open.** `init()` reads `props`, picks the tab (prop, else the tab used last: `LAST_TAB`), and restores the last graph read for the same folder from the module-level `CACHE`, so the first paint is instant. It then starts a 5 s timer that calls `refresh()`.
2. **Where.** `where()` is `props.folder` when given, otherwise the focused pane's cwd (`location()`, also resolving a remote machine). `ctx()` is that value as a string; a change of context resets branch, rows and selection.
3. **Refresh.** `refresh()` finds the repo root once (`rev-parse --show-toplevel`), then reads `for-each-ref`, `rev-parse HEAD`, `symbolic-ref` and `rev-list --left-right --count @{upstream}...HEAD`, `status --porcelain=v2` and the in-progress probe from `status.js` (these update `work`/`inprog` on every refresh and repaint when they change, but are not part of the graph signature); with no upstream it also reads `config --get branch.<name>.merge` to tell "never had one" from "deleted on the remote". `branch`, `sync` and `upstreamGone` are assigned together, after the `config --get` read and before the graph read, so Push never sees a mixed state. The graph itself (`git log`, 400 per page) is re-read only when the signature of refs, HEAD, branch, counts and limit changed, or when the last read failed (it is retried on every refresh). A `watchFolder` loop triggers extra refreshes for local repos.
4. **Render.** `render()` forwards to `renderPanel()` (`render.js`), which builds the tab row, the controls row, the note bar, the body and the detail panel from small functions (`tabsRow`, `toolbarRow`, `noteBar`, `progressBanner`, `commitList`, `moreBar`). Lists use `v_virtual_list` with handlers on the list (`on_item_click`), never inside a row renderer. Rows get a lane column from `layout()` output. The commit search is a view-side filter: `renderPanel()` calls `hits()`, which finds matches among the loaded rows (memoized on the rows array and the text), and `commitRow()` only dims non-matches and tints the current match; no git command is involved.
5. **Act.** Fetch, Pull, Push, branch switch/create, the guarded writes of [ADR-007](../decisions/ADR-007-allow-guarded-local-writes.md) (branch/tag/detached checkout at a commit, cherry-pick and revert, `--abort` of the operation in progress, branch rename and delete, stash push/apply/pop/drop) PR checkout and the GitHub writes of [ADR-009](../decisions/ADR-009-allow-guarded-pull-request-writes.md) (merge, close, ready for review, delete head branch) all go through `op()`: one operation at a time, `exec(cmd, argv, { cwd: root })` with no shell, the result shown as text in the note bar, then a forced `refresh()`. `op()` can run a read-only precondition first (`extra.check(run, gh)`) and show a refusal instead; a two-click action (Push, stash pop and drop, branch delete, cherry-pick, revert, abort, and the four PR writes) is armed by `confirm(key)`, which holds one action key for 5 s; the key names the full target (the commit and branch, the stash entry and its commit, the branch and its hash, the operation and its id), so arming one target never arms another.
6. **Inspect.** Selecting a commit runs `git show` (message, `--numstat`, `--name-status`, `-m --first-parent`); a file click runs `git show` for that path and `setDiff()` builds the rows, `markWords()` the intra-line highlight. A `History` button on a file's diff swaps the diff for that file's `git log --follow` list (`history.js`). The PR tab does the same with `gh pr view` and `gh pr diff`, parsed by `splitDiff()`.

## Ownership and boundaries

- The view owns all state; the functions of every module take it as `v` and mutate it through `v`. Modules call each other by import, downwards only (`render` -> `detail` -> `writes` -> `ops` -> `shared`/`ui`); a call back up goes through a method of the view, so there are no import cycles. Nothing outlives the overlay except `CACHE` and `LAST_TAB`.
- Read-only git is run with `--no-optional-locks` and `core.fsmonitor=false` so the mod's own reads never trigger its folder watch. The Config tab's `git config --list` is the exception: it takes no locks, and those `-c` flags would show up as `command`-scope rows.
- The lists of the Refs tab and the Config tab only read (`for-each-ref`, `stash list`, `reflog`, `config --list`). Writes to git are limited to `fetch --all --prune`, `pull --ff-only`, `push`, `switch` (including `--track`, `-c` and `--detach`), and the guarded writes of [ADR-007](../decisions/ADR-007-allow-guarded-local-writes.md): `branch <name> <hash>`, `tag` (lightweight or `-a -m`), `stash push --include-untracked`, `stash apply <hash>`, `stash pop stash@{n}` and `stash drop stash@{n}`, `branch -m`, `branch -d`, `cherry-pick`, `revert --no-edit` and `--abort` for a merge, rebase, cherry-pick or revert; writes through `gh` to `pr checkout` (a local branch switch) and the four of [ADR-009](../decisions/ADR-009-allow-guarded-pull-request-writes.md): `pr merge`, `pr close`, `pr ready` and `api -X DELETE` of a merged PR's head ref. The mod never creates or reviews a PR. See the ADRs below.
- The repo copy is the source for sharing; the running app loads `~/.config/herdr-app/mods/git-panel/`. They are kept in sync by hand ([runbook](../runbooks/sync-live-copy.md)).
